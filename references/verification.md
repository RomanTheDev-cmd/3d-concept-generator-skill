# Проверка поведения при изменении навыка

Пять примеров проверяют реальные изображения, а не совпадение формулировок инструкций. Новые изображения запускаются только когда пользователь явно запросил тестовую генерацию или конкретные примеры. Просьба проверить/исправить инструкции или обновить версию сама по себе не запускает этот набор: используй сценарии без генерации и доступные сохранённые данные. Не генерируй весь набор при обычном обращении пользователя. Палитры здесь — тестовые данные автора набора, не пользовательские значения по умолчанию.

1. Двухцветный робот: синий корпус, белая лицевая панель, синие углубления глаз, одна белая прямоугольная метка на правом предплечье самого робота. Голова, туловище, две руки и две ноги; вид 3/4, прозрачный фон. Проверить, не добавился ли чёрный для глаз, не появился ли пол и сохранена ли метка.
2. Сюрреалистичная скульптура: единая лента-петля с двумя крупными сквозными отверстиями и четырьмя чистыми цветными сегментами (синий, красный, жёлтый, белый), без подставки, прозрачный фон. Проверить читаемость обоих отверстий, отсутствие дополнительных цветов/эффектов и целостность силуэта. Это визуальная проверка, не доказательство топологии реальной сетки.
3. Декоративная ветка: один стебель, три листа, два тонких изогнутых усика, фиолетовый стебель/усики и белые листья; прозрачный фон. Проверить число частей, их соединения и края тонких элементов. Не объявлять их прочность доказанной.
4. Перекрасить только синюю часть робота из примера 1 в красную, сохранив белые детали, геометрию, положение частей, ракурс и композицию. Использовать фактическое изображение 1. Проверить форму и наличие метки до/после.
5. Показать того же робота из примера 1 строго сзади. Спереди белая лицевая панель, остальная голова синяя; не придумывать белую панель на затылке. Сохранить белую метку на правом предплечье робота (со спины она справа в кадре). Проверить число частей, асимметрию, палитру и масштаб; скрытое отметить как скрытое.

Для каждого сохранить реальный запрос, изображение, основу для правок, результат визуального просмотра, доступные файловые проверки и известные отклонения. Итоги по критериям: PASS / PARTIAL / FAIL / NOT_CHECKED, с конкретной причиной. Авторский проход в текущем чате не является слепым или независимым испытанием другой модели и не проверяет автоматически поведение обычного ChatGPT/Work.

Вдобавок без генерации проверить: отсутствующие цвета вызывают один вопрос о палитре; команда показа карточки не создаёт картинку; перенос не требует Mac; откат возвращает существующий файл; отсутствие основы не маскируется новым похожим изображением. Проверка схем/файлов не заменяет эту смысловую оценку.

## Сценарии без новой генерации

Сопоставь правила с ветвлением истории v1 → v2 и отдельно v1 → вариант B: «верни предыдущую» из B возвращает v1; «прими v2» делает v2 текущей и утверждённой. Впервые запрошенная серия ракурсов не требует промежуточного принятия основного кадра. Белый фон и заданная подставка не дают ложного FAIL. Повторный вид сзади не требует механически менять сторону асимметричной детали. Перекраска заменяет палитру текущей цветовой версии, а не объединяет цвета всей истории.
